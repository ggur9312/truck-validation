# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A browser bookmarklet (Korean UI) that automates a warehouse WMS's "집품 현황 조회" (pick-status lookup) page: scan a tote barcode → auto-search → detect truck vs. courier delivery → verify scanned products against expected quantities → for courier shipments, auto-open the WMS's waybill-generation modal and drive it via a scannable virtual barcode. There is no access to the real WMS; all development is verified against a hand-rolled mock (`test/fixture.html` + `test/server.js`).

`package.json`'s `test:smoke` script only wires up `smoke.js` + `smoke_truck.js` — the other smoke files above are not in any npm script and must be run individually. There is no test runner/framework; each file is a plain Node script that `console.log`s `OK:`/`FAIL:` lines and sets `process.exitCode`. Every smoke test starts its own instance of `test/server.js` (a plain `http` server on port 8934) as a side effect of `require`, so run smoke tests as separate `node` processes (as above), not concurrently in the same process.

After any change to `src/bookmarklet.js`, run **all** of the commands above (unit test + all 17 smoke files) before considering the change done, then `node build.js` and sanity-check `dist/bookmarklet.txt` (e.g. `node -e "new Function(require('fs').readFileSync('dist/bookmarklet.txt','utf8').replace(/^javascript:/,''))"`) — `dist/bookmarklet.txt` is the actual shipped artifact and is committed to git (not gitignored), so it must be rebuilt and committed alongside any `src/` change.

## Architecture

**Everything lives in one file, `src/bookmarklet.js`.** It is a single IIFE prefixed with the `javascript:` scheme (a labeled statement, not a syntax error) and has zero runtime dependencies — no CDN, no bundler, no framework. This is a hard constraint, not an oversight: the target network's CSP blocks external scripts, so the CODE128B barcode encoder + `<canvas>` renderer is hand-written inline (`code128Values`/`code128Patterns`/`drawCode128`) rather than pulled from a library.

Top-of-file constants are the seams for adapting to a real WMS whose DOM differs from the mock:
- `SEL` — every DOM selector the script touches on the *host* WMS page (tote input, search button, date-range picker, waybill dialog, etc.)
- `CTRL` — the short strings (`TVCS`/`TVCW`/`TVCR`) encoded into the virtual barcodes; kept intentionally short (4 chars) because the CODE128 module count — and therefore the on-screen widget width — scales directly with string length (this was cut down from `TVCTL_WAYBILL`-style 13-char codes in a prior round specifically to shrink the floating barcode without thinning the bars past scannable width)

**Virtual barcode mechanism**: barcode scanners are keyboard-emulation devices. A CODE128 barcode is rendered on a `<canvas>`; scanning it types the encoded string into whatever's focused, followed by Enter. The global `keydown` listener (`onGlobalKeydown`) buffers keystrokes and uses inter-key timing to distinguish scanner input (fast) from human typing (slow), then checks whether the buffered string starts with `TVC` to route it to `handleScan` as a control code vs. letting it fall through as a real product/tote/box barcode typed into the WMS's own input.

**State machine**: `state.mode` drives everything (`IDLE` → `SEARCHING` → `VERIFYING` → `WAITING_WAYBILL_OPEN` → `WAITING_WAYBILL` → `REFRESHING` → `REPRINT_READY` → back to `IDLE`). Most functions are guarded by a mode check so stray scans in the wrong state are no-ops.

**UI isolation**: a single host `<div>` is appended to `document.documentElement` with `attachShadow({mode:'open'})`; the entire stylesheet is one big JS string (`CSS`) injected as a `<style>` tag inside the shadow root, using CSS custom properties (`--tv-*` tokens on `:host`) for the whole light theme (see below). Nothing is written to global document styles.

**Every component now shares one light theme, except the top-right status badge**: `:host`'s `--tv-surface`/`--tv-surface-2`/`--tv-surface-3`/`--tv-text`/`--tv-text-soft`/`--tv-border`/`--tv-success-tint` tokens carry the light palette (`#ffffff`/`#eef1f7`/`#e2e6f0`/`#161a26`/`#5b6274`/`rgba(20,25,45,.1)`/`rgba(52,211,153,.22)`) that `.tv-verify` used to override locally — that override is gone now since it's redundant, so `.tv-verify` only sets structural properties (width/max-height/padding/overflow/flex). This single change re-themed every component that references these tokens (the settings card, status toast, mismatch modal, reprint/waybill barcode popovers) without touching each one individually; `.tv-simplified-*` was already light via hardcoded hex rather than these tokens, so it's unaffected either way. `.tv-status-badge` and `.tv-reprint-area` (the top-left reprint virtual-barcode popover) are the two deliberate exceptions, by request: each carries its own local dark override of the same handful of tokens (the original pre-unification dark palette: `#1b2132`/`#242b40`/`#2d3552`/`#f2f4fa`/`#aab3c6`/`rgba(255,255,255,.09)`) directly in its own rule, the same technique `.tv-verify` used to use — descendants like `.tv-status-badge-main`/`.tv-status-badge-waybill-label`/`.tv-float-label` that reference `var(--tv-text)`/`var(--tv-text-soft)`/`var(--tv-surface)` pick it up automatically since they're plain `var()` references with no color baked in locally. `.tv-reprint-area`'s override was added, removed, then re-added on request across rounds — it started dark (pre-unification), briefly went light with everything else, then was explicitly reverted back to dark. `--tv-accent`/`--tv-success`/`--tv-error`/`--tv-truck-*`/`--tv-courier-*`/`--tv-restricted-*`/`--tv-elev-*` are unrelated to surface color and were left as-is everywhere.

**Waybill modal detection, worth knowing before touching the waybill-watching logic:** the real WMS's waybill modal is a persistent `<div id="modalOutboundWaybill">` — it is never added to or removed from the DOM by opening/closing; instead its `class` toggles between `waybill-overlay is-open` (open) and `waybill-overlay` (closed). `findWaybillModalNode()` therefore treats presence of the `is-open` class on `SEL.waybillDialog` (`#modalOutboundWaybill`) as the *authoritative* open/closed signal when that element is found at all — it does **not** fall back to geometry checks for it, since a hidden-but-still-rendered descendant (e.g. via `visibility`/`opacity` instead of `display:none`) could report nonzero `offsetWidth`/`offsetHeight` forever and mask a real close. Geometry-based visibility (`isElementVisible`, via `offsetWidth`/`offsetHeight`/`getClientRects().length`) is used only for the two fallback candidates (`SEL.waybillSubmit`/`SEL.waybillBoxInput`), which is what kicks in when `SEL.waybillDialog` doesn't match at all (real WMS markup drifted from our assumed id — see `smoke_fallback.js`). Because the modal is a persistent element with a toggled class rather than a node that gets inserted/removed, `watchWaybillDialog()`'s `MutationObserver` watches `attributes`/`class` (not just `childList`) so a manual close is caught immediately instead of waiting for the 400ms poll fallback.

**Group-number loading restriction (상차제한)**: settings has a `restrictedGroups` field (comma-separated raw string, edited via the `.tv-group-input` text field in the settings modal, `placeholder="예: 1234567,4567890"` — changed from a 2-digit example on request since real group numbers are 7 digits, parsed on demand by `getRestrictedGroupList()`) and a `restrictionEnabled` boolean (the `SETTING_DEFS`-driven "그룹번호 상차제한" toggle switch). The actual restriction decision in `processRow()` is `state.settings.restrictionEnabled && getRestrictedGroupList().indexOf(restriction.groupNo) !== -1`; both the switch and the group list must agree for a tote to be treated as restricted. The `.tv-group-field-row` text input is only rendered visible when `restrictionEnabled` is true, and is rendered *directly below its own toggle row* (not grouped with other fields at the bottom) — `renderSettingsHTML()` sets its initial `tv-hidden` state from that flag, and the toggle's `change` handler in `bindSettingsEvents()` additionally toggles it live by checking `cb.dataset.key === 'restrictionEnabled'` directly (not generalized across `SETTING_DEFS`, since each toggle currently gates a differently-shaped field below it). The group number, creation date, and vendor name shown when restricted all come from the *same* detail document already being fetched for truck/courier detection (`linkType`, the 3rd `<td>`'s link) — `parseRestrictionInfo(doc)` reads the group number from that doc's 1st table/1st `<td>`, the creation date from the 1st table/6th `<td>` (sliced to the first 10 chars to normalize to `YYYY-MM-DD` in case the real WMS includes a time component), and the restricted-vendor name from its 2nd table/1st `<td>`, which is a different field from `info.vendor` (fetched from the *other* detail link, `linkProduct`/1st `<td>`, 1st table/5th `<td>`) even though both are commonly the same company in practice. When the tote's group number matches, `state.toteInfo.isRestricted` is set and `openVerifyModal()` renders the type banner in an orange `restricted` variant (see the delivery-type tile paragraph below for its current label/detail/value structure) instead of the normal truck/courier one — and `afterVerification()` checks `isRestricted` before `isTruck`, so a restricted tote always ends after verification (no waybill modal), the same as the truck flow, even if it's actually a courier delivery.

**Creation-date loading restriction** works the same way as group-number restriction but as an independent, OR'd condition (`isRestricted = groupRestricted || dateRestricted` in `processRow()`) — either one alone is enough to restrict a tote. `state.settings.dateRestrictionEnabled`/`dateRestrictionStart`/`dateRestrictionEnd` (the `.tv-date-start-input`/`.tv-date-end-input` native `<input type="date">` fields, which get the browser's own calendar picker for free) drive `isDateInRestrictedRange()`. **The range is open-ended on either side**: only a start date restricts that date and everything after it (`dateStr >= start`); only an end date restricts that date and everything before it (`dateStr <= end`); both together form the usual inclusive closed range — all via plain string comparison, which works correctly for zero-padded ISO dates without any `Date` object / timezone handling. The status-badge date line mirrors this: a closed range reads `생성일시 : start ~ end` (spaced), but an open-ended range reads `생성일시 : start~` or `생성일시 : ~end` (no spaces around the lone `~`) — see the ternary in `updateRestrictBadge()`.

**트럭검증 간소화 (simplified mode) skips per-product verification entirely.** `state.settings.simplifiedMode` (default off, resets on every load like every other setting) is checked in `processRow()` right after `state.toteInfo` is resolved (isTruck/isRestricted/dateRestricted/restrictedVendor/restrictedDate all get set on it same as the normal path) and *before* `buildExpectedMap()`/`openVerifyModal()` would otherwise run — when on, the verify modal is never built at all. `showSimplifiedNotice()` always fires first regardless of delivery type (a bottom-right `.tv-simplified-notice` popover showing an icon, the vendor name, the scanned tote barcode, and 집품수량 in `EA` units — colored per delivery type, same semantic scheme as everywhere else in the file: green for courier, red for truck, orange for restricted, driven by a `--tv-notice-fg` custom property set via a `.truck`/`.courier`/`.restricted` class on the notice itself). **The tote barcode line lost only its label, not the barcode itself**: it originally read "토트번호 <값>", then "스캔토트 <값>", then briefly (one round) got deleted outright along with its value — that last change went further than requested, so `.tv-simplified-notice-tote` is back as a plain `escapeHtml(info.toteBarcode)` with no leading label text, directly under the vendor line inside `.tv-simplified-notice-info`, sharing the exact same `19px`/`600`/`#161a26`/`white-space:nowrap` styling as `.tv-simplified-notice-vendor`. The notice was widened (`300px`→`380px`) and its text enlarged on request since it was easy to miss. `.tv-simplified-notice` itself is `width:max-content` (not a fixed px value) with the vendor/tote lines `white-space:nowrap` and `.tv-simplified-notice-info`/`-icon`/`-qty` all `flex-shrink:0` — a long vendor name or tote code grows the *card's width* instead of wrapping to extra lines, per request (an earlier round tried wrapping via `word-break:break-all` on a fixed `380px` card, which grew the card *taller* instead — not what was wanted). **`showSimplifiedNotice()` fires for every row `processRow()` can resolve, independent of which action button that row currently carries** — `processRow()` computes `hasReprintBtn`/`hasWaybillBtn` up front and only short-circuits straight to `showReprintOverlay()` *before* fetching detail data when simplified mode is *off* (the pre-existing fast path, unchanged); when simplified mode is on, a row with the reprint button (an already-generated waybill) still goes through the same `Promise.all([fetchDoc(linkProduct.href), fetchDoc(linkType.href)])` detail fetch as every other row so the notice reflects that tote's *actual* freshly-queried vendor/qty/type, and only after `showSimplifiedNotice()` does it branch to `showReprintOverlay()` instead of the block-modal/waybill path. Previously the reprint-button row never reached the fetch at all, so the notice was left showing stale data (or none) from whatever was scanned before — see `smoke_simplified_mode.js` scenario 2b (`TOTE_REPRINT`, backed by dedicated `/detail/TOTE_REPRINT` + `/type/TOTE_REPRINT` routes in `test/server.js`). Then: a courier tote (`!isTruck && !isRestricted`) calls `proceedToWaybill()` directly (extracted out of `afterVerification()`'s courier tail so both the normal post-verification path and this simplified path share it — `afterVerification()` itself is otherwise unchanged); a truck or restricted tote calls `openSimplifiedBlockModal()` instead, ending the flow there with no waybill step, mirroring today's truck/restricted behavior of stopping after verification. **The notice has no close button of its own** — an earlier round had a `.tv-simplified-notice-close` button (using `ICONS.close`) in its top-right corner, but that was removed on request; `showSimplifiedNotice()` no longer renders it and no longer binds a click handler for it, and `.tv-simplified-notice`'s right padding shrank back from `40px` to a symmetric `20px` now that there's no button to clear. The notice is dismissed only by being overwritten by the next scan's content, or by turning `simplifiedMode` back off (the `.tv-activate-btn` click handler in `bindSettingsEvents()` calls `hideSimplifiedNotice()` when saving settings with `simplifiedMode` now false, since otherwise a notice shown while the setting was on would stay visible indefinitely after the setting is switched off — nothing else would ever clear it) — it does not auto-hide on a timer. `hideSimplifiedNotice()` itself is unchanged (still clears the popover and its innerHTML), it's just no longer reachable via a button click.

**Every pictographic icon in the whole file is hand-drawn inline SVG, not emoji or a plain text glyph** — all live in one object, `ICONS` (originally `SIMPLIFIED_ICONS`, renamed once its 3 delivery-type icons started being reused by the product verification modal too — see below). Each entry is 24x24 viewBox, ~2.3-2.8px stroke, `stroke-linecap`/`stroke-linejoin: round` for soft corners, no drop shadows, filled circles/solid accents only where needed, `stroke="currentColor"`/`fill="currentColor"` throughout so the surrounding element's own `color` drives the per-context tint with zero extra CSS (e.g. `.tv-simplified-icon{color:rgb(var(--tv-aura))}` in the block modal, `.tv-verify-header-icon.truck{color:var(--tv-truck-fg)}` in the verify modal). `ICONS.truck` was redesigned once already — the original shape (a plain rectangle plus an open L-shaped stroke meant to suggest a hood, no windshield or cab/trailer divider) read as an ambiguous box, not a truck; the current shape follows the well-established "cargo rect + separate closed-trapezoid cab + two wheel circles" composition (the same construction principle Feather's `truck` icon uses, redrawn in this file's own stroke/currentColor style) so the cab and cargo box are visually distinct and the wheels sit under the body. `ICONS.vendor` (건물 실루엣 + 4개 창문 점, 업체명 스탯타일) and `ICONS.tote` (정면 상자 + 뚜껑 접힘선 + 세로 테이프 이음선, 토트바코드 스탯타일) were added alongside the redesign so the verify modal's stat tiles no longer use emoji either — `ICONS.tote`'s front-on box shape is deliberately different from `ICONS.courier`'s isometric hexagon box so the two don't look identical next to each other. `ICONS.qty` (three ascending filled bars, a small bar-chart) was added in a later round for the 전체 집품수량 stat tile (see below). `ICONS.close`/`ICONS.check`/`ICONS.mismatch`/`ICONS.printer`/`ICONS.waybill` round out the set for every remaining icon-like character in the file (see the dedicated paragraph below). `ICONS.courier` is only ever used inside the bottom-right notice and the verify modal's courier state (a courier tote never opens the block modal), so it has no `--tv-aura`-variant counterpart.

**All non-delivery-type icons (close buttons, checkmarks, the mismatch modal's alert icon, the waybill/reprint labels) were also swept from emoji/text-glyph to `ICONS.*` SVGs in the same round.** Every `title="닫기"` close button (`.tv-mismatch-close`, `.tv-verify-close`, `.tv-simplified-close`, `.tv-simplified-notice-close`) now renders `ICONS.close` (an X-mark path) instead of the literal `✕` character, each with its own `<class> svg{width;height}` sizing rule since SVGs don't respond to `font-size` the way a text glyph does. `.tv-mismatch-icon` (the big icon at the top of the blocking mismatch modal) uses `ICONS.mismatch` (a circle + X, deliberately different from the plain X of `ICONS.close` so a status icon doesn't read as a button) instead of `❌`, with an explicit `color:var(--tv-error)` added since SVG needs a `currentColor` source that emoji glyphs never needed (native emoji carry their own built-in color). The two `markProductScan()` mismatch messages ("등록되지 않은 상품 바코드입니다" / "이미 스캔 완료된 상품입니다") had their `❌ ` text prefix dropped rather than getting their own inline icon — `.tv-mismatch-message` is set via `.textContent` (plain sentence, no wrapper span), and the modal already shows the big `ICONS.mismatch` icon above it, so a second small icon inline with the text would just duplicate that signal. `showStatus()`'s toast icon (`✕`/`✓` for error/success; loading still uses the pre-existing CSS-only `.tv-spinner`, which was never an emoji) now renders `ICONS.close`/`ICONS.check`; the color still comes from the pre-existing `.tv-status-card.error .tv-status-icon`/`.tv-status-card.success .tv-status-icon` rules, unchanged. The product row's own completion checkmark (`.tv-product-status`, both the initial `renderProductRowHtml()` render and the later dynamic update in `markProductScan()`) and `updateScanStatusPill()`'s "정상"/"불일치" pill now use `ICONS.check`/`ICONS.close` — the pill switched from `.textContent` to `.innerHTML` (icon + a wrapping `<span>` for the Korean word) and gained `display:inline-flex;align-items:center;gap:4px` so the icon and text line up.

**The status badge's 상차제한 header and the waybill/reprint floating labels also moved off emoji, and the waybill label's centering bug got fixed in the same pass.** `.tv-status-badge-restrict-header`'s static "🚫 상차제한 활성화 중" markup (since renamed to "상차제한 활성화", see below) now wraps `ICONS.restricted` (reusing the same icon the block modal uses, not a new one) in a `<span class="tv-status-badge-restrict-icon">` ahead of the text — the div was already `display:flex;align-items:center;justify-content:center;gap:8px` so this needed no layout change beyond sizing the child svg. `showWaybillOverlay()`'s "📮 스캔하여 운송장생성" label and `showReprintOverlay()`'s "🖨 운송장 재출력" label similarly got wrapped in an icon span (`ICONS.waybill`/`ICONS.printer`) ahead of the text. **`.tv-status-badge-waybill-label` had a real (if easy to miss) alignment bug**: unlike `.tv-float-label` (whose ancestor `.tv-float-area` already sets `text-align:center`, so the reprint label was always centered), `.tv-status-badge-waybill-label` had no `text-align`/layout rule of its own and sat inside `.tv-status-badge-waybill`, a block whose width is set by its *widest child* — normally the barcode canvas, which is wider than the label text — so the shorter label text rendered flush against the left edge of that wider box instead of centered over the barcode below it. Both labels now get `display:flex;align-items:center;justify-content:center;gap:6px` directly (rather than relying on inherited `text-align`), which simultaneously fixes that alignment bug for the waybill label and gives both labels a controlled gap between their new icon and the Korean text. See `smoke.js`'s `.tv-status-badge-waybill-label` `justifyContent === 'center'` assertion.

`openSimplifiedBlockModal()` sets `state.mode = 'SIMPLIFIED_BLOCK'` and renders `.tv-simplified-block` (inside the always-present-but-empty `.tv-simplified-overlay` wrapper — that wrapper itself never carries `tv-card`, only the inner card built via `innerHTML` does, preserving the single-`.tv-card`-at-rest invariant every smoke test's first assertion depends on). Visually it follows the reference design: a colored header bar (red for truck / orange for restricted) reading "운송유형 확인" with a white close icon, a large icon circle + bold underlined 트럭/상차제한 title, and two description lines — plus a continuously pulsing `rgba(...)`-based aura on the card's own `box-shadow` (one shared `tvAuraPulse` keyframe, colored per type via a `--tv-aura` custom property rather than duplicated per type). The description line(s) differ by type: truck shows a single static reference line ("해당 토트는 트럭 운송 토트입니다." — worded "상품" originally, changed to "토트" on request to match the verify modal's type-hero subtitle wording; a second line, "택배 스캔 시 오류가 발생할 수 있습니다.", was removed on request earlier as redundant/unnecessary); restricted shows `info.restrictedVendor` and, only when the tote is *also* `dateRestricted`, a second "생성일시 : ..." line — a group-only restriction shows just the vendor line, matching how the vendor/date disclosure rule is already spec'd for this feature (group ⇒ vendor only, date ⇒ vendor + date). **The modal has no confirm button and no auto-close timer** — it is dismissed only by its own close button, a bare Enter keypress, or scanning any barcode at all. The scan-dismiss path reuses the exact same "early `return` while an overlay's `tv-show` class is present" pattern the mismatch modal already established in `onGlobalKeydown()`: every keystroke of a scan burst gets swallowed before it ever reaches `scanBuf.chars.push`, so only the trailing Enter actually triggers the close and the scanned content itself is silently discarded (never treated as a new tote search or product scan).

**Every setting resets on every load, none persist** — `restrictionEnabled`/`restrictedGroups` used to be the exception (persisted, `restrictionEnabled` defaulted `true`) but that was changed on request: now `SETTINGS_RESET_ON_LOAD` lists every key in `SETTINGS_DEFAULTS` (both toggles off, all three text/date fields empty), so a fresh load or reload always starts from a fully blank slate — the localStorage read/write plumbing (`loadSettings()`/`saveSettings()`) is kept as-is for architectural consistency (and in case a future non-restriction setting needs to persist), it just currently has no persisting effect since every key is in the reset list. **Pitfall already hit once**: `SETTINGS_DEFAULTS`/`SETTINGS_RESET_ON_LOAD` must be declared *before* `var state = { settings: loadSettings(), ... }`, not after — `var` hoisting only hoists the name binding, not the assignment, so if `loadSettings()` runs before those two vars are assigned, they're `undefined` at that point, `SETTINGS_RESET_ON_LOAD.forEach` throws, and the `try/catch` in `loadSettings()` silently swallows it into an empty settings object (every toggle defaults unchecked, every field hidden) — no visible error, just wrong defaults.

**Search-result row must be validated before verification starts**: `startSearch()` compares the resolved row's 1st `<td>` (the same text the WMS itself shows as the tote identifier) against the barcode that was actually scanned, via `td(row, 0) !== toteBarcode` — a mismatch (stale/wrong result) is rejected with a toast instead of silently verifying the wrong tote. `processRow()` then separately requires the last `<td>` to contain either the reprint button (`.btn-waybill-print-single`) or the waybill-generation button (`[data-action="open-waybill-modal"]`); a row with *neither* is a tote that cannot be loaded at all and is rejected with "상차 불가한 토트입니다" before ever fetching detail pages or opening the verify modal. See `smoke_row_validation.js` (fixture scenarios `TOTE_MISMATCH` and `TOTE_NOBTN`).

`.tv-status-overlay` (all `showStatus()` toasts) is anchored `align-items:flex-start` with `padding-top:90px`, not vertically centered — this is deliberate so a toast never visually collides with the verify/settings modals it often appears alongside.

**Watch out for the `overflow-x`/`overflow-y` coupling gotcha**: per the CSS Overflow spec, setting only one of `overflow-x`/`overflow-y` to a non-`visible` value computes the *other* axis to `auto` too (never `visible`) if left unset. `.tv-product-list` only needs vertical scrolling (`overflow-y:auto`), but leaving `overflow-x` unset made it implicitly `auto` as well — and a product row's error-shake animation (`tvRowFocusErr`, `translateX` up to 6px) transiently pushed `scrollWidth` past `clientWidth`, flashing a real horizontal scrollbar on every mismatched/duplicate scan. Any scrollable container that should only scroll on one axis needs the other axis pinned to `hidden` explicitly, not left to default.

**Row scan-feedback glow must use `inset` box-shadow, not an outward one**: `.tv-product-row` sits flush against `.tv-product-list`'s edges with zero horizontal gutter, and that list has `overflow-x:hidden` (see the coupling gotcha above). An *outward* `box-shadow` ring (`tvRowFocus`/`tvRowFocusErr`, the blue "scanned correctly" / red "mismatch" glow) bleeds past the row's own left/right edges to render the ring — but those edges coincide exactly with the list's own clip boundary, so the left/right (and most of each rounded corner's outward curve) got silently clipped away, leaving only the top/bottom edge strips and the slivers of each corner nearest the clip boundary visible — which reads as "only the corners flash" instead of the whole row lighting up. Both keyframes now paint the ring with `inset` (`box-shadow:inset 0 0 0 5px rgba(...)`), which stays entirely within the row's own border box and can never be clipped by an ancestor's `overflow`, regardless of how tight the surrounding gutter is. The `tvRowFocusErr` shake's `translateX` transform is unrelated to this and is untouched — it still visibly clips at its most extreme frames, which is the accepted tradeoff that keeps the scrollbar from flashing (see above).

**Verify modal height capping**: `.tv-verify` has `max-height:88vh` and is itself a column flex container (header + body), so with enough products the *card* can never grow past the viewport the way it used to. See `smoke_many_products.js`.

**Reprint barcode stays available for repeat use**: `doReprint()` deliberately does *not* hide `.tv-reprint-area` or move `state.mode` out of `REPRINT_READY` after a successful reprint — some totes genuinely need reprinting more than once (lost/damaged label), so the barcode must stay scannable indefinitely. The only way out of `REPRINT_READY` is scanning a new tote barcode (handled by `handleScan`'s `REPRINT_READY` branch, which hides the stale overlay and starts a fresh search).

**Watch out for the `CSS` name collision**: the file's own top-level stylesheet variable is `var CSS = '...'`, which shadows the global `window.CSS` namespace object *everywhere in this file's scope*. Calling `CSS.escape(...)` will silently resolve to a property on the stylesheet string, not the browser API, and throw `CSS.escape is not a function` at runtime — this bit us once already. Find elements by attribute value via a manual `Array.prototype.filter` over `.children` (see `findProductRow`) instead.

**Row/element animations use a specific pattern to avoid killing each other**: several CSS keyframe animations are triggered by adding a class, and re-triggered later by `classList.remove(cls); void el.offsetWidth; classList.add(cls)` (forces a reflow so the animation restarts). Entrance animations (`.tv-row-enter`) are intentionally *not* combined with `animation-fill-mode: forwards` on the same element that later gets a different animation class (`.tv-row-pop`/`.tv-row-focus`) — two different animation-name values on overlapping classes fully override each other (CSS `animation` is not additive across selectors), so relying on `forwards` to hold a value (e.g. opacity) breaks the moment a second animation class gets added later. Give each transient animation its own modifier class with a self-contained resting state instead of depending on fill-mode carryover from an earlier one.
